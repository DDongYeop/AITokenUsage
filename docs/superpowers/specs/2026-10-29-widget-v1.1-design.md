# AI 사용량 위젯 v1.1: 남은 시간 · 다국어 · 설정 창 개편 · 설치 프로그램

- 날짜: 2026-10-29
- 기준: v1.0 설계 `2026-10-28-ai-usage-taskbar-widget-design.md`(이하 "v1.0 설계"). 이 문서에 적지 않은 동작은 v1.0 설계를 그대로 따른다.
- 사용자 결정
  - 남은 시간은 % 옆에 작게 표시
  - 지원 언어는 한국어 + 영어. Windows 표시 언어를 따르고, 설정에서 바꿀 수 있다
  - 설정 창의 불편한 점(4가지 모두): 길어서 스크롤해야 함, AI 줄이 복잡함, 연결 방법을 모름, 모양이 구식임
  - 설치는 Inno Setup으로 만든 Setup.exe
  - 설정 창은 방식 A: .NET 10 WPF 기본 Fluent 테마에 직접 만든 왼쪽 메뉴, 토글, 카드

## 1. 범위

**하는 것**
1. 위젯의 각 줄에 초기화까지 남은 시간을 짧은 형식으로 표시한다.
2. 모든 사용자 문자열을 리소스로 옮기고 한국어와 영어를 지원한다.
3. 설정 창을 왼쪽 메뉴 + 카드 구조로 다시 만들고, AI별 연결 방법을 안내한다.
4. .NET 런타임을 포함한 사용자 단위 설치 프로그램(Setup.exe)을 만든다.

**하지 않는 것**
- 자동 업데이트, 코드 서명(서명이 없으므로 첫 실행 시 SmartScreen 경고가 나올 수 있다)
- 한국어와 영어 외의 언어. 구조는 언어를 추가하기 쉽게 만든다
- 앱이 CLI를 대신 설치하는 기능. 명령을 안내하고, 사용자가 누르면 터미널을 열어 줄 뿐이다
- 언어를 바꿨을 때 다시 시작하지 않고 바로 적용하는 기능

## 2. 위젯: 초기화까지 남은 시간

### 2.1 레이아웃
```
 ✳ Claude   5h ▰▱▱▱▱▱   1%  4h12m       폭 약 218 DIP (남은 시간 표시 켜짐)
   ● ○ ○    주 ▰▰▰▰▱▱  75%   2d3h       폭 176 DIP (꺼짐, v1.0과 같음)
```
- 각 줄은 라벨(24), 바(44), 간격(4), 값(32, 오른쪽 정렬), 간격(4), **남은 시간(38, 오른쪽 정렬)** 순서다.
- 남은 시간은 10px이고, 보조 텍스트 색(불투명도 0.65)이다.
- 위젯 폭
  - 남은 시간 표시가 켜져 있으면 218 DIP, 꺼져 있으면 176 DIP다. (처음에는 30 DIP 열로 210이었으나 `23h59m`이 잘려 38 DIP로 넓힘)
  - `TaskbarLayoutCalculator`는 고정 상수 대신 폭을 인자로 받는다.
  - 공간이 부족하면 숨기는 규칙은 v1.0 설계 §4.3과 같다.
- 텍스트 줄(Copilot의 `↻ 11/1` 같은 리셋 날짜 줄)과 상태 메시지 줄에는 남은 시간을 표시하지 않는다.
- 설정 "위젯 표시 > 초기화까지 남은 시간"은 기본 켜짐이다.

### 2.2 짧은 형식 (`CompactDurationFormatter`, Core)
언어와 관계없이 같은 형식을 쓴다. 공간이 좁아서 단위 글자 `d/h/m`만 쓴다.

| 남은 시간 | 표시 |
|---|---|
| 초기화 시각 없음 | (빈칸) |
| 1분 미만 (지난 시각 포함) | `<1m` |
| 1분 이상 1시간 미만 | `42m` |
| 1시간 이상 24시간 미만 | `4h12m`. 분이 0이면 `4h` |
| 1일 이상 10일 미만 | `2d3h`. 시간이 0이면 `2d` |
| 10일 이상 | `12d` |

- 분 단위 이하는 버린다(내림). v1.0의 `FormatRelative`와 같다.
- 위젯은 30초마다 남은 시간만 다시 계산한다. 데이터를 새로 받아 오지는 않는다.
- 상세 카드는 지금처럼 전체 문구를 쓴다. 예: `2일 3시간 후 · 10/31(금) 05:00` / `in 2d 3h · Fri 10/31 5:00 AM`

## 3. 다국어 지원

### 3.1 리소스 구조
- **Core**: `src/AITokenUsage.Core/Resources/Strings.resx`(기본 = 영어)와 `Strings.ko.resx`(한국어)
  - 대상: 상태 문구, 공급자 메시지, 미터 라벨, 시간·날짜 형식, 트레이 툴팁
- **App**: `src/AITokenUsage/Resources/UiStrings.resx`와 `UiStrings.ko.resx`
  - 대상: XAML과 코드 비하인드의 모든 UI 문구, 메뉴, 접근성 이름(`AutomationProperties.Name`), 툴팁
- **강타입 클래스**: MSBuild `EmbeddedResource`의 `StronglyTypedLanguage`/`StronglyTypedClassName`/`StronglyTypedNamespace` 메타데이터로 빌드할 때 만든다.
  - 계획의 첫 Task에서 이 방식이 SDK 빌드에서 동작하는지 확인한다.
  - 동작하지 않으면 `Microsoft.CodeAnalysis.ResxSourceGenerator` 패키지로 바꾼다. 두 경우 모두 사용하는 코드는 `Strings.Connected` 형태로 같다.
- **XAML에서 쓰는 방법**: `{x:Static res:UiStrings.SettingsTitle}`
- **형식 문자열**: 자리표시자가 있는 문구는 `string.Format(CultureInfo.CurrentCulture, Strings.X, ...)`로 만든다. 예: `"{0} 후 · {1} {2}"` / `"in {0} · {1} {2}"`
- **서식 키** (언어마다 리소스에 둔다)
  - 시각 형식: ko `HH:mm`, en `h:mm tt`
  - 날짜+요일 형식: ko `{0}/{1}({2})`, en `{2} {0}/{1}`
  - 요일 이름은 `CultureInfo.DateTimeFormat.AbbreviatedDayNames`를 쓴다.
- **바꾸지 않는 것**
  - 로그 메시지(영어 유지)
  - 설정 파일의 키와 미터 키(`session`, `weekly` 등)
  - AI 이름(Claude, Codex, Gemini, Copilot)

### 3.2 언어 선택
- 설정에 `Language` 속성을 추가한다. 값은 `"auto"`(기본), `"ko"`, `"en"` 중 하나이고, 그 밖의 값은 `Normalize`가 `"auto"`로 고친다.
- `auto`이면 Windows UI 언어(`CultureInfo.InstalledUICulture`)의 두 글자 코드가 `ko`일 때 한국어, 그 외에는 영어를 쓴다.
- **적용 시점**: 앱이 시작될 때, UI를 만들기 전에 정한다.
  - `CultureInfo.DefaultThreadCurrentCulture`, `DefaultThreadCurrentUICulture`, 현재 스레드의 `CurrentCulture`, `CurrentUICulture`를 모두 같은 문화권으로 설정한다.
  - 결정 로직(`LanguageResolver`)은 Core에 두고 단위 테스트한다.
- **언어를 바꾸면**
  - 설정 창에 "다시 시작하면 적용돼요"와 [지금 다시 시작] 버튼이 나온다.
  - [지금 다시 시작]은 설정을 저장한 뒤 새 프로세스를 띄우고 현재 프로세스를 끝낸다.
  - 새 프로세스는 `--restarted` 인자를 받으면 단일 인스턴스 뮤텍스가 풀릴 때까지 최대 5초 기다린다.
- 캐시(`cache.json`)에 저장된 공급자 메시지는 저장할 때의 언어로 남아 있다가, 다음 조회에서 새 언어로 바뀐다. 이 정도는 허용한다.

### 3.3 테스트
- **리소스 완전성 테스트**: 기본 resx의 모든 키가 `ko` resx에도 있고, 값이 비어 있지 않고, `{n}` 자리표시자 개수가 같아야 한다. Core와 App resx 모두 검사한다(App resx는 파일을 XML로 읽어서 검사).
- **기존 테스트**: 한국어 문자열을 기대하는 기존 테스트에는 `[UseCulture("ko-KR")]` 속성(xUnit `BeforeAfterTestAttribute`)을 붙인다.
- **새 테스트**: 영어 결과를 검증하는 테스트를 주요 포매터마다 추가한다.

## 4. 설정 창 개편

### 4.1 창
- **테마**: 창 단위 `ThemeMode="System"`(.NET 10 WPF Fluent)을 쓴다.
  - 실험 단계 API 경고 `WPF0001`은 App 프로젝트 `NoWarn`에 넣는다.
  - 위젯 창과 상세 카드에는 적용하지 않는다.
- **크기**: 기본 760×540 DIP, 최소 640×460이고 크기 조절이 가능하다. 화면 가운데에 연다.
- **적용 방식**: v1.0처럼 바꾸면 즉시 적용하고 자동 저장한다.
- **구조**: 왼쪽 메뉴(폭 200)와 오른쪽 페이지로 나눈다. 페이지는 각각 `UserControl`이고, 내용이 넘칠 때만 페이지 안에서 스크롤한다.

### 4.2 공통 컨트롤 (`src/AITokenUsage/UI/Controls/`)
- **`SettingsCard`**: 둥근 카드(모서리 6, Fluent 카드 배경 브러시)다. 왼쪽에 제목과 설명(작은 글씨), 오른쪽에 컨트롤을 둔다.
- **`ToggleSwitchStyle`**: `CheckBox`용 스위치 모양 템플릿이다. 접근성은 CheckBox 그대로 두고, 오른쪽에 `켬/끔` 텍스트를 붙인다.
- **`StatusBadge`**: 색 점과 짧은 상태 텍스트다.

  | 상태 | 색 |
  |---|---|
  | 연결됨 | 초록 `#2EA043` |
  | 로그인 필요 / 갱신 대기 | 주황 `#F5A524` |
  | 설치 안 됨 / 지원 안 됨 | 회색 |
  | 오류 / 요청 제한 | 빨강 `#F04438` |

- **펼친 내용**

**일반** (`GeneralPage`)

### 4.4 연결 방법 안내 (`ConnectionGuide`, Core)
상태와 AI에 따라 단계 목록을 만드는 순수 함수다.

```csharp
ConnectionGuide? ConnectionGuideBuilder.Build(string providerId, ProviderStatus status, string? statusMessage)
// 연결됨이거나 안내할 것이 없으면 null
public sealed record ConnectionGuide(IReadOnlyList<GuideStep> Steps, string? Footnote);
public sealed record GuideStep(string Text, string? Command, GuideAction Action);   // Command가 있으면 [복사]
public enum GuideAction { None, OpenTerminal, OpenUrl, Recheck }
```

| AI | 상태 | 단계 |
|---|---|---|
| Claude | 설치 안 됨 | ① Node.js 설치 `winget install OpenJS.NodeJS.LTS` (이미 있으면 건너뛰기) ② `npm install -g @anthropic-ai/claude-code` ③ [터미널에서 로그인] → `claude` 실행 후 `/login` |
| Claude | 로그인 필요 | [터미널에서 로그인] → `claude` 실행 후 `/login` |
| Claude | 갱신 대기 | "Claude Code를 한 번 실행하면 로그인이 갱신돼요" + [터미널 열기] → `claude` |
| Codex | 설치 안 됨 | ① Node.js ② `npm install -g @openai/codex` ③ [터미널에서 로그인] → `codex login` |
| Codex | 로그인 필요 | [터미널에서 로그인] → `codex login` |
| Gemini | 설치 안 됨 | ① Node.js ② `npm install -g @google/gemini-cli` ③ [터미널에서 로그인] → `gemini` 실행 후 "Login with Google" 선택 |
| Gemini | 로그인 필요 | [터미널에서 로그인] → `gemini` |
| Gemini | 지원 안 됨(개인 계정 종료) | 안내 문구만: "개인 Google 계정은 Gemini CLI 사용량 조회가 종료됐어요. Workspace(Code Assist) 계정이 필요해요" |
| Copilot | 로그인 필요 | `CopilotSignInPanel`(기기 코드 로그인) |
| 모든 AI | 위 상태 | 마지막 줄: "로그인하면 자동으로 인식돼요" + [다시 확인] |

- **[터미널에서 로그인]**
  - Windows Terminal(`wt.exe`)이 PATH에 있으면 `wt.exe new-tab cmd /k <명령>`, 없으면 `cmd.exe /k <명령>`으로 새 창을 연다.
  - 명령은 위 표에 있는 고정 문자열만 쓴다. 사용자 입력을 섞지 않는다.
  - UI 스레드 밖에서 `Process.Start`로 실행하고, 실패하면 카드에 "터미널을 열지 못했어요. 명령을 복사해 직접 실행해 주세요"를 표시한다.
- **[다시 확인]**: 해당 AI만 즉시 새로고침한다(`UsageService`의 기존 수동 새로고침 경로).
- 로그인 파일이 바뀌면 기존 `ProviderPathWatcher`가 감지해서 자동으로 새로고침한다.

## 5. 설치 프로그램

### 5.1 배포본
- `dotnet publish src/AITokenUsage -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:PublishReadyToRun=true -o artifacts/publish`
- .NET 런타임을 포함하므로 .NET이 없는 PC에서도 실행된다. 설치 파일은 약 60–80MB가 예상된다.
- 버전은 `Directory.Build.props`의 `<Version>1.1.0</Version>` 하나에서 관리한다. 앱의 정보 페이지와 설치 프로그램이 이 값을 쓴다.

### 5.2 Inno Setup 스크립트 (`installer/AITokenUsage.iss`)
- **설치 권한·위치**
  - `PrivilegesRequired=lowest`라서 관리자 권한이 필요 없다.
  - `DefaultDirName={localappdata}\Programs\AITokenUsage`
- **식별**: `AppId`는 고정 GUID다. 이 값을 바꾸면 업그레이드가 새 설치로 취급되므로 바꾸지 않는다.
- **언어**: 설치 화면은 한국어와 영어다(`Korean.isl`, `Default.isl`). Windows 언어로 자동 선택한다.
- **실행 중인 앱 처리**: `AppMutex=Local\AITokenUsage.SingleInstance`, `CloseApplications=yes`. 설치·업그레이드·제거 시 실행 중인 앱을 닫도록 안내한다.
- **바로가기**: 시작 메뉴에 만든다. 바탕화면 아이콘은 선택 항목(기본 해제)이다.
- **선택 항목 "Windows 시작 시 자동 실행"** (기본 해제)
  - `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에 `AITokenUsage` = `"<설치 경로>\AITokenUsage.exe"`를 쓴다. 앱의 `StartupRegistration`과 같은 값 이름과 형식이다.
- **설치 완료 화면**: "AI 사용량 실행" 체크(기본 체크)
- **제거**
  - Run 값 `AITokenUsage`를 지운다.
  - "설정과 캐시도 삭제할까요?"를 묻는다(기본 아니요). 예를 고르면 `%APPDATA%\AITokenUsage`와 `%LOCALAPPDATA%\AITokenUsage`를 지운다.
  - 이 폴더에는 DPAPI로 암호화된 Copilot 토큰도 들어 있다. CLI 자격 증명 파일(`~/.claude` 등)은 절대 건드리지 않는다.
- **결과물**: `artifacts/installer/AITokenUsage-Setup-<버전>.exe`

### 5.3 시작 등록과 설정의 동기화
설치 프로그램이 Run 값을 쓰면 앱 설정과 실제 상태가 달라질 수 있다. 이를 맞추기 위해 다음 규칙을 둔다.
- 앱이 시작되면 백그라운드에서 Run 값을 읽는다. 값이 **현재 실행 파일 경로를 가리키면** `StartWithWindows = true`로 설정에 반영하고 저장한다.
- 그 밖의 경우(값이 없거나 다른 경로)에는 v1.0처럼 설정값을 기준으로 등록하거나 해제한다.
- 판정 함수(`StartupSync.Decide(currentValue, processPath, settingEnabled)`)는 Core에 두고 단위 테스트한다.

### 5.4 빌드 스크립트 (`tools/Build-Installer.ps1`)
1. ISCC를 찾는다.
   - 찾는 순서: `%ProgramFiles(x86)%\Inno Setup 6`, `%ProgramFiles%\Inno Setup 6`, `%LOCALAPPDATA%\Programs\Inno Setup 6`
   - 없으면 `winget install JRSoftware.InnoSetup` 안내를 출력하고 끝낸다(스크립트가 직접 설치하지 않는다).
2. `dotnet test`를 실행하고, 실패하면 중단한다.
3. §5.1 publish를 실행한다.
4. `Directory.Build.props`에서 버전을 읽어 `ISCC /DAppVersion=<버전> installer/AITokenUsage.iss`를 실행한다.
- `artifacts/`는 이미 `.gitignore`에 들어 있다.

## 8. 위험 요소

| 위험 | 대응 |
|---|---|
| `ThemeMode`가 실험 단계 API라 이후 .NET에서 바뀔 수 있음 | 설정 창 한 곳에서만 쓰고, 경고 억제도 App 프로젝트에만 둔다 |
| MSBuild 강타입 resx 생성이 SDK 빌드에서 동작하지 않을 수 있음 | 첫 Task에서 확인하고, 안 되면 `ResxSourceGenerator`로 바꾼다(§3.1) |
| 영어 문구가 길어서 위젯의 상태 문구나 라벨이 잘릴 수 있음 | 위젯 라벨은 2–3자 약어(`5h`, `Wk`, `Mo`)를 쓰고, 상태 문구는 짧은 키(`Sign in`, `Not installed`)를 따로 둔다 |
| 서명이 없는 Setup.exe에 SmartScreen 경고가 나옴 | README에 "추가 정보 → 실행" 안내를 적는다 |
| Inno Setup이 이 PC에 없음 | 사용자 동의를 받고 `winget`으로 설치한다. 동의가 없으면 스크립트와 .iss까지만 만들고 컴파일 확인은 남긴다 |
